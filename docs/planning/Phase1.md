# Phase 1: 项目初始化与设置功能开发规划评审

**版本**: 1.1
**更新日期**: 2026-02-01
**状态**: 已完成

## 1. 当前阶段目标
本阶段旨在构建项目的基础设施，并完成核心的“卡林巴配置”业务模块，为后续的音频分析与乐谱生成奠定基础。

*   **基础设施就绪**：完成技术栈搭建，确保开发环境稳定，确立代码规范与工程化标准。
*   **配置能力闭环**：实现卡林巴乐器的数字化建模，支持用户选择预设（17/21键）或完全自定义调音，提供直观的可视化预览。
*   **数据持久化**：建立基于 IndexedDB 的本地存储方案，确保用户配置安全持久化，为后续存储大体积音频数据做技术铺垫。

## 2. 设计方案

### 2.1 系统架构
*   **应用层**：采用 React 18 SPA 架构，使用 Vite 作为构建工具。
*   **状态管理**：使用 Zustand 管理全局配置状态（`SettingsStore`），实现响应式数据流。
*   **存储层**：设计抽象的存储接口，底层封装 IndexedDB 适配层，替代 LocalStorage 以支持结构化数据与大文件存储。
*   **样式层**：基于 Tailwind CSS 构建原子化样式体系，集成 Mint/Lovable 设计风格。

### 2.2 模块划分
*   **基础设施模块**：
    *   路由系统 (`react-router-dom`)
    *   全局布局 (`Layout`)
    *   通用 UI 组件 (`Button`, `Card`, `Input` 等)
*   **设置业务模块** (`SettingsPanel`)：
    *   **预设管理**：提供标准卡林巴配置的快速切换。
    *   **自定义构建器**：支持用户定义键数、调式。
    *   **调音编辑器**：提供每个琴键的音高微调能力，支持音名/MIDI 输入。
    *   **可视化预览**：基于 SVG 的动态乐器渲染，实时反馈配置变更。
*   **领域模型** (`Domain`)：
    *   `KalimbaConfig`：乐器配置聚合根。
    *   `Tuning`：调音值对象。

### 2.3 数据模型
*   **配置存储结构** (IndexedDB: `settings` store)
    *   `currentKalimbaId`: 当前选中的配置 ID。
    *   `customKalimbas`: 自定义配置列表。
    *   `version`: 数据版本号，用于迁移。

## 5. 验证标准
*   **功能验收**：
    *   用户能成功切换 17/21 键预设，预览图即时更新。
    *   用户能创建自定义配置并保存，刷新页面后配置不丢失且状态一致。
    *   调音编辑器能正确拦截非法的音名输入，并给出友好提示。
*   **技术验收**：
    *   应用在 Chrome/Edge/Safari/Firefox 最新版均可正常运行。
    *   Lighthouse 性能评分 > 90。
    *   核心业务逻辑测试覆盖率 > 80%。

## 6. 风险与预警
*   **存储迁移风险** (低)：已实现 `zustandIdbStorage` 适配器，包含自动数据迁移逻辑（LocalStorage -> IndexedDB）。测试用例已验证迁移的正确性与异常处理。
*   **配置兼容性** (中)：自定义配置的数据结构需设计版本控制字段，以应对未来可能的字段变更（如增加“按键颜色”、“材质”等属性），防止数据结构升级导致旧数据无法读取。
