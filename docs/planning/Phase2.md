# Phase 2 开发规划：音频上传与预处理

**版本**: 1.0
**更新日期**: 2026-02-01
**状态**: 规划中

## 1. 当前阶段目标
本阶段的核心目标是建立可靠的音频输入管道，确保用户能够顺畅地将本地音频文件导入系统，并进行必要的前置校验和预处理，为后续的音频分析和乐谱生成奠定基础。

**核心业务价值**:
- **构建输入入口**: 提供用户与系统交互的第一步，支持便捷的文件导入方式。
- **保障数据质量**: 通过严格的校验机制（格式、时长、大小），拦截不符合要求的输入，避免后续处理资源的浪费。
- **建立数据基座**: 完成音频文件的本地持久化存储，确保用户数据的安全性和应用的离线可用性。

## 2. 设计方案

### 2.1 系统架构与流程
本阶段主要涉及表现层（上传组件）、业务逻辑层（任务控制）和存储层（IndexedDB）的交互。

```mermaid
graph LR
    User[用户] -->|拖拽/选择| UploadUI[上传组件]
    UploadUI -->|文件流| Validator[输入校验模块]
    Validator -->|校验通过| Metadata[元数据提取]
    Metadata -->|音频数据| Storage[存储服务 (IndexedDB)]
    Metadata -->|任务状态| StateStore[状态管理 (Zustand)]
    Validator -->|校验失败| ErrorHandler[错误处理模块]
    ErrorHandler -->|错误提示| UploadUI
```

### 2.2 模块划分
- **用户交互模块**:
  - **文件上传区**: 支持拖拽和点击选择，提供视觉反馈（悬停、加载中）。
  - **信息录入**: 允许用户编辑音频标题和其他元数据。
  - **状态反馈**: 展示校验结果、上传进度和错误信息。

- **业务逻辑模块**:
  - **输入校验器**: 负责检查文件类型（MP3）、文件大小（<50MB）和音频时长（<10分钟）。
  - **音频预处理器**: 使用 Web Audio API 获取音频元数据（时长、采样率等），不进行完整解码以节省内存。
  - **任务协调器**: 管理上传任务的生命周期，对接存储服务。

- **数据存储模块**:
  - **IndexedDB 适配器**: 负责音频二进制数据 (Blob) 和元数据的存取操作。

### 2.3 数据模型设计
- **音频源数据 (AudioSource)**:
  - 基础信息：ID, 标题, 文件名, 上传时间
  - 技术参数：文件大小, 时长, 格式 (MIME type)
  - 存储引用：指向 IndexedDB 中的 Blob 键值

## 5. 验证标准
- **功能验收**:
  - [ ] 能够成功上传 5MB, 20MB, 45MB 的标准 MP3 文件。
  - [ ] 上传非 MP3 文件时，UI 能够准确提示格式错误。
  - [ ] 上传超过 50MB 的文件时，UI 能够准确提示大小超限。
  - [ ] 上传超过 10 分钟的音频时，能够被拦截并提示时长超限。
  - [ ] 页面刷新后，已上传的音频信息和文件能够从 IndexedDB 恢复。
- **性能验收**:
  - [ ] 文件校验耗时 < 500ms。
  - [ ] 文件保存到本地数据库耗时 < 1s (针对 10MB 文件)。
- **代码质量**:
  - [ ] 核心逻辑单元测试覆盖率 > 80%。
  - [ ] 无关键 ESLint 错误。
